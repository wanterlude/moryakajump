# Симулятор забегов Moryaka Jump

Собирает `sim.html` — копию игры с ботом и хуками для массовых прогонов.
В репозиторий и в exe не попадает, только для тестов.

## Быстрый старт

```bash
node tools/sim/make_sim.js          # собрать sim.html из index.html
node tools/sim/run-node.js --runs=500
```

Флаги: `--runs` (по умолчанию 500), `--steps` (максимум шагов на забег, 600000),
`--chunk` (сколько миллисекунд считать за одну порцию, 2000).

Скорость — около 3,2 забега в секунду: 500 забегов ≈ 2,5 минуты, 5000 ≈ 26 минут.
Результаты: `last-run.json` (сырые забеги), `last-run.md` (сводка),
`last-run.log` (прогресс). Все три файла в `.gitignore`.

Браузер не нужен: `run-node.js` загружает `sim.html` в обычный Node через
`dom-shim.js` — минимальные заглушки DOM и canvas (рисование отключено, бот
двигает `update()` сам). Внешних зависимостей нет.

## Прогон в браузере

Если нужен настоящий canvas (проверить отрисовку, а не только физику):

```bash
node tools/sim/make_sim.js
python -m http.server 8765
# открой http://127.0.0.1:8765/sim.html
```

В консоли браузера:

```js
__simInit(200, 600000);   // сколько забегов и максимум шагов на забег
__simChunk(4000);         // считать ~4 секунды, вызывать повторно
__simMachine.runs         // результаты: score, cause, boss, duelStartLives, ...
__simMachine.done         // true, когда все забеги завершены
```

Отдельная проверка дуэли: `__simDuelTest(index, lives, maxSteps)` —
запускает бой с боссом и возвращает число попаданий, HP босса и победу.

## Что умеет бот

- Идёт по безопасным платформам, обходит шипы, полыньи и птиц.
- Собирает монеты и сердечки: монеты дают жизни (25 за жизнь, с перками — меньше),
  это критично, потому что босс с 0 жизней проигрывается мгновенно.
- Выбирает перки: жизни → множитель монет → монеты-за-жизнь → щиты → двойной прыжок.
- В дуэли использует MPC: откатывает состояние боя, перебирает точки перемещения
  на 40 кадров вперёд и выбирает вариант без попаданий. С 1 жизнью выигрывает
  почти все дуэли без единого попадания.

## Сравнение с базовой линией 1.0.24

Прежний прогон (5000 забегов) делался до смягчения ветра в 1.0.25 и до
страховой жизни при входе к боссу в 1.0.29.

| Метрика | 1.0.24 | 1.0.33 | Изменение |
|---|---|---|---|
| Медиана | 19 932 | 19 864 | −0,3% |
| 90-й перцентиль | 33 542 | 38 349 | +14,3% |
| Максимум | 100 623 | 122 757 | +22,0% |
| ≥ 30 000 | 817 (16,3%) | 783 (15,7%) | — |
| ≥ 60 000 | 46 (0,9%) | 64 (1,3%) | +0,4 п.п. |
| Смерти от падения | 80,6% | 84,6% | +4,0 п.п. |
| Входов в дуэль | 866 | 783 | −9,6% |
| Дуэлей без попаданий | 250 (28,9%) | 760 (97,1%) | +68,2 п.п. |
| Дуэлей с 0 жизней | 360 (41,6%) | 0 | — |

Что это значит:

- **Середина распределения не изменилась**, а хвост вырос: играть стало легче
  на высоких высотах (мягче ветер), но типичный забег остался прежним.
- **Дуэли перестали быть угрозой для бота.** Страховая жизнь убрала входы с
  0 жизнями, а MPC с одной жизнью выигрывает почти без попаданий. Смертей с
  причиной «дуэль» больше нет вообще.
- **Главная причина смерти — падение** (84,6% против 80,6%): доля выросла не
  потому, что стало сложнее падать, а потому что перестали убивать дуэли и
  боссы.
- Бот почти не ошибается в дуэли, поэтому эти цифры — про механику, а не про
  живого игрока. Для честной оценки сложности дуэли нужна модель с промахами.

## Как добавить метрику

Сырые забеги лежат в `last-run.json`; агрегаты считает `summary.js`
(`summarize()` и `toMarkdown()`). Набор полей забега формируется в `run-node.js`.
