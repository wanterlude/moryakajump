# Прототип: PixiJS + TypeScript + Vite

Не часть игры. Это замер, чтобы решить, стоит ли переносить рендер на PixiJS.

## Что здесь есть

| Файл | Что делает |
|---|---|
| `src/scene.ts` | детерминированная сцена: платформы, снежинки, герой |
| `src/layout.ts` | чистая математика магнитного поля — **общая для обоих рендереров** |
| `src/canvasRenderer.ts` | отрисовка текущим способом (Canvas 2D, immediate mode) |
| `src/pixiRenderer.ts` | та же сцена на PixiJS (retained mode, спрайты в батче) |
| `src/main.ts` | запускает оба, замеряет время кадра, пишет `window.__bench` |
| `test/layout.test.ts` | тесты раскладки и сцены — без браузера и GPU |

## Команды

```
npm install
npm run check     # tsc --noEmit + тесты (≈0.1 с, процессор не грузит)
npm run build     # сборка в один файл: dist/index.html ≈ 530 КБ (gzip 152 КБ)
npm run dev       # посмотреть глазами в браузере
```

Замер в браузере (headless Chrome, софтверный WebGL):

```
node tools/pixi-test.js           # лёгкий сценарий
node tools/pixi-test.js --heavy   # тяжёлый: процессор уходит в 100 %, только осознанно
```

## Замеры

Сцена 400×600, 180 кадров, headless Chrome на SwiftShader (софтверный GPU).

| Сценарий | Canvas 2D | Pixi, наивный порт | Pixi, спрайты в батче |
|---|---|---|---|
| 6 платформ, 140 снежинок | 0.074 мс | — | **0.038 мс** (1.9×) |
| 30 платформ, 700 снежинок | 0.606 мс | 53.3 мс (**в 46 раз хуже**) | **0.122 мс** (5.0×) |

Числа — процессорная часть кадра. На реальном GPU разрыв в пользу Pixi был бы больше,
на софтверном — меньше; важен порядок, а не десятые доли.

## Главный вывод

Переписать `ctx.fill()` в `new Graphics()` один к одному — **катастрофа**: каждая
фигура становится отдельным дравколлом, и на тридцати платформах с кольцами поля
получается ~400 вызовов и 53 мс на кадр вместо 0.6 мс.

Работает только «правильный» Pixi: всё повторяющееся запекается в текстуры
(платформа, кольцо, полюс, снежинка, небо) и рисуется спрайтами, которые Pixi
склеивает в один батч. Тогда число платформ почти не влияет на число дравколлов.

## Чего прототип не покрывает

- HUD, меню, магазин, диалоги — в игре это 94 DOM-элемента и ~50 функций канваса.
- `shadowBlur` (37 мест) — в Pixi это фильтры, их стоимость другая и мерить надо отдельно.
- `clip()` (28 мест) — маски, каждая лишний объект.
- Реальная сцена игры: 8 платформ одновременно, но со скинами, эффектами и событиями.
